# UI / Design-System Audit

**Summary (3 lines)**

1. The hot-path `globals.css` defines a rich Tailwind v4 `@theme inline` token set (`good/warn/bad/terra`, `canvas-parchment`, `surface-tile-*`, etc.), yet many seller pages and tables bypass it and reach for raw Tailwind palette utilities (`bg-rose-50`, `text-amber-800`, `bg-zinc-100`, `bg-red-500`, `bg-orange-100`) and hand-written hex colors (`#1d1d1f`, `#0066cc`, `#c2410c`, `#e8e3da`, `#FF6058`, `#E5C0A6`). This is the single largest token-discipline problem and shows up across `seller/orders`, `seller/listings`, `seller/welcome`, and the seller layout.
2. The shadcn primitive layer is small but solid (Card/Button/Select/AlertDialog/Form), however page-level code largely reinvents UI in raw `<button>`, `<table>`, and `<div className="space-y-…">` instead of composing those primitives — that's exactly the anti-pattern the `shadcn` skill calls out (use existing components, not custom markup), and it cascades into a11y issues (icon-only `<button>` actions, native tables without TableHead semantics, custom toggles missing roles).
3. The task brief references `src/web/src/components/primitives.tsx` and a "26-touch hot path" — that file does not exist in the tree and there are no `primitives` imports anywhere under `src/web/src` (verified with `grep -rn primitives src/web/src`). The "primitives" hot path is therefore audited as the de-facto primitive layer, which is `src/web/src/components/ui/*` plus the seller shell.

### [Critical] Raw Tailwind color utilities bypass the semantic token system
- **Where**: `src/web/src/components/seller/listings/listings-table.tsx:31-33`, `:179-181`, `:196`; `src/web/src/components/seller/orders/orders-inbox-table.tsx:63`, `:70`; `src/web/src/components/seller/orders/order-detail-timeline.tsx:33`; `src/web/src/components/seller/orders/order-detail-fulfillments.tsx:31`, `:84`; `src/web/src/app/seller/orders/[id]/page.tsx:63`; `src/web/src/components/seller/listings/new-listing-form.tsx:129`.
- **Issue**: Status colors are hard-coded to Tailwind's stock palette — `bg-amber-50 text-amber-800` (low stock), `bg-rose-50 text-rose-700` (out), `bg-zinc-100 text-zinc-700` (draft), `bg-red-50 text-red-700` (bad orders), `bg-red-500` (dot), `bg-orange-100 text-orange-700` (fulfilled). The repo already ships semantic tokens `--good / --warn / --bad / --terra` (and even `--good-soft`) mapped through `@theme inline` in `globals.css:113-118` and even uses `bg-good/15 text-good` on the same line (`listings-table.tsx:30`). The mix is the problem: dark-mode swaps and brand re-tints will skip these utilities entirely.
- **Skill rule**: `shadcn` -> `rules/styling.md` *"Use semantic colors. `bg-primary`, `text-muted-foreground` — never raw values like `bg-blue-500`."*; `ui-ux-pro-max` Quick Reference §6 `color-semantic` *"Define semantic color tokens … not raw hex in components."*; `tailwind-design-system` Design-Token Hierarchy.
- **Fix**: Replace all status palette calls with `bg-warn/15 text-warn`, `bg-bad/15 text-bad`, `bg-muted text-muted-foreground` (draft), and `bg-good-soft text-good`. Add a `--color-bad-soft` token if a tinted error background is needed beyond `/15`.

### [Critical] Hard-coded hex colors embedded in page markup
- **Where**: `src/web/src/app/seller/layout.tsx:10` (`bg-white text-[#1d1d1f]` on the shell root); `src/web/src/app/seller/first-order/page.tsx:20,75,104,139,148` (`#0066cc`, `#c2410c`); `src/web/src/app/seller/first-month/page.tsx:10-12` (`{ clay: "#c2410c", sage: "#4d7c3f", cream: "#d4b896" }`); `src/web/src/app/seller/listings/[sku]/preview/page.tsx:97-99,126,162,166` (`#E8E3D8`, `#FF6058`, `#FFBD2E`, `#28C941`, `#e2d5c8`, `#c2410c`, `#F0E8D7`); `src/web/src/app/seller/states/first-sale/page.tsx:87` (`#0066cc`); `src/web/src/app/seller/orders/page.tsx:36` (`text-[#1d1d1f]` on a button); `src/web/src/components/seller/orders/order-detail-customer.tsx:11` (`bg-[#e8e3da] text-[#1d1d1f]`); `src/web/src/components/seller/listings/listings-table.tsx:37-40` (`TONE_BY_CATEGORY` uses `bg-[#E5C0A6]`, `bg-[#C9D4BC]`, `bg-[#F0E8D7]`); `src/web/src/components/seller/shared/sparkline.tsx:3` (default `text-[#0066cc]`).
- **Issue**: These bypass the `@theme inline` token map entirely, will never respond to dark-mode overrides in `globals.css:141`, and duplicate values that already exist as tokens (`--primary`, `--surface-avatar-warm`, `--terra`, `--ink`). The traffic-light hexes in the preview page (`#FF6058 / #FFBD2E / #28C941`) are decorative chrome glyphs — they should at minimum live in a constant, not be inlined per usage.
- **Skill rule**: `ui-ux-pro-max` Quick Reference §6 `color-semantic` ("not raw hex in components"); `tailwind-design-system` Token Hierarchy; `building-components` `design-tokens.mdx`.
- **Fix**: Replace `text-[#1d1d1f]` → `text-foreground`/`text-ink`, `#0066cc` → `bg-primary text-primary-foreground`, `#c2410c` → `bg-terra`, `#e8e3da` → `bg-surface-avatar-warm`. Move the macOS-window swatches into a single `TRAFFIC_LIGHTS` const reused across mocks, or expose them as `--mock-traffic-{red|amber|green}` if they really are part of the design system.

### [Critical] Native `<table>` markup duplicates the shadcn `Table` primitive
- **Where**: `src/web/src/app/seller/first-order/page.tsx:122-134`; `src/web/src/app/seller/listings/bulk/page.tsx:140-142`; `src/web/src/app/seller/listings/published/page.tsx:118-129`; `src/web/src/app/seller/listings/[sku]/edit/page.tsx:140-142`; `src/web/src/app/seller/payouts/page.tsx:128-130`; `src/web/src/components/seller/orders/orders-inbox-table.tsx:82-83`. Only `listings-table.tsx` actually imports from `@/components/ui/table`.
- **Issue**: The shadcn `Table` primitive is installed and used in exactly one place; six other surfaces re-implement table styling inline with `<table className="w-full text-sm"><thead><tr className="border-b…">…`. Every table therefore has its own border colors (`border-black/[0.06]`, `border-black/[0.04]`, `border-border`) and its own header typography (`text-[11px] uppercase tracking-wider text-muted-foreground` vs `text-foreground/50`). Visual drift is guaranteed.
- **Skill rule**: `shadcn` -> Principles #1 ("Use existing components first") and Critical Rules "Use Components, Not Custom Markup"; `building-components` principles (composability, primitives reuse).
- **Fix**: Migrate the seller tables to `Table / TableHeader / TableRow / TableHead / TableBody / TableCell` from `@/components/ui/table` and centralize the header typography there.

### [High] Inline `<button>` elements re-implement `Button` styles and bypass focus rings/active states
- **Where**: `src/web/src/app/seller/page.tsx:27`, `:36` (Export + "+ New listing" — even the primary CTA is a `<Link>` styled with raw classes, not the `Button` primitive with `asChild`); `src/web/src/app/seller/orders/page.tsx:34,41`; `src/web/src/app/seller/first-order/page.tsx:61`; `src/web/src/app/seller/first-month/page.tsx:64,71`; `src/web/src/app/seller/states/empty-orders/page.tsx:32`; `src/web/src/app/seller/states/first-sale/page.tsx:170`; `src/web/src/app/seller/listings/new/page.tsx:15`; `src/web/src/app/seller/marketing/page.tsx:18`.
- **Issue**: The `Button` primitive (`components/ui/button.tsx`) already wires `focus-visible:border-ring`, `aria-invalid:ring-destructive/20`, `active:not-aria-[haspopup]:translate-y-px`, icon slot CSS, and a `Base UI` polymorphic root. Hand-rolled buttons get *none* of that, and they re-declare colors like `bg-primary px-4 py-2 text-sm font-medium text-white hover:bg-primary/90` per-call. Result: focus rings, disabled opacity, and pressed states are inconsistent across the seller surface.
- **Skill rule**: `shadcn` Principle #3 ("Use built-in variants before custom styles") and Component Selection table ("Button/action -> `Button` with appropriate variant"); `ui-ux-pro-max` Quick Reference §1 `focus-states`.
- **Fix**: Replace the seller-page `<button className="rounded-full …">` and `<Link className="rounded-full bg-primary …">` with `<Button variant="default" size="lg">` and `<Button asChild variant="default"><Link …/></Button>` so the shared focus/active/disabled CSS applies everywhere.

### [High] Custom switch/toggle widgets bypass the shadcn `Switch` and miss ARIA roles
- **Where**: `src/web/src/components/seller/marketing/email-composer-schedule.tsx:14-18`, `src/web/src/components/seller/marketing/email-composer-audience.tsx:59-63`, `src/web/src/components/seller/listings/new-listing-form.tsx:401-402` (`<div className="w-8 h-4 rounded-full bg-good …"> <div className="w-3 h-3 rounded-full bg-white" /></div>`).
- **Issue**: These render a switch-shaped div with an inline `transform: translateX(14px)` style, no `role="switch"`, no `aria-checked`, no keyboard handling, no focus ring. There is also no `Switch` primitive installed (`ls components/ui` shows none), which means the gap is structural — the design uses switches but the system never adopted one.
- **Skill rule**: `shadcn` Component Selection ("Toggle between 2-5 options -> `ToggleGroup`"; form inputs -> `Switch`); `ui-ux-pro-max` §1 `aria-labels`, `focus-states`; `building-components` `accessibility.mdx`.
- **Fix**: `npx shadcn@latest add switch` and replace the hand-rolled toggles. Until then, at minimum add `role="switch"`, `aria-checked`, and keyboard support to the existing divs.

### [High] `Sparkline` chart is decorative-only and not screen-reader friendly
- **Where**: `src/web/src/components/seller/shared/sparkline.tsx:1-30` (default `className="h-8 w-full text-[#0066cc]"`, fixed `aria-label="Sparkline chart"`).
- **Issue**: Three problems in one component: (a) a hard-coded `#0066cc` default that bypasses `text-primary`; (b) an `aria-label` that's identical for every instance and conveys zero data; (c) no fallback summary (e.g., delta, first/last, peak) — the shape is the only signal. `ui-ux-pro-max` Quick Reference §10 specifically calls out `screen-reader-summary` and `color-not-only`.
- **Skill rule**: `ui-ux-pro-max` §10 `screen-reader-summary`, `color-not-only`, `tooltip-keyboard`; `shadcn` Component Selection ("Charts -> `Chart` (wraps Recharts)").
- **Fix**: Default the color to `text-primary`, accept a required `label` prop ("Revenue, last 30 days, +18%"), and render an `aria-describedby` summary or `<title>` element inside the SVG with first/last/peak values.

### [High] React Compiler is on, but the form layer is hand-fixed with `"use no memo"` instead of being migrated
- **Where**: `src/web/src/components/ui/form.tsx:1-9` ("`useFormField` reads `formState` off `useFormContext()` … the one pattern that still breaks under React Compiler GA … Required errors never render in FormMessage … Long-term: rewrite useFormField on top of `useFormState({ control })`"); also `src/web/src/components/seller/listings/new-listing-form.tsx:148,169,278,320,346,376,436` use `space-y-*` on `FormItem` which the comment already calls "the one pattern that breaks".
- **Issue**: The escape hatch in the file's own TODO is intentional debt — but it's now load-bearing for the whole seller forms area. Anyone who copies a `<FormField>` to a non-form context will silently lose validation. Combined with the `space-y-*` violations in `new-listing-form.tsx`, the form layer drifts further from the shadcn forms ruleset every iteration.
- **Skill rule**: `shadcn` -> `rules/forms.md` ("Forms use `FieldGroup` + `Field`. Never use raw `div` with `space-y-*` or `grid gap-*` for form layout."); MEMORY.md note `project_react_compiler_rhf_gotcha`.
- **Fix**: Track the migration: rewrite `useFormField` on `useFormState({ control })` so the directive can be dropped, then replace ad-hoc `space-y-*` `FormItem` overrides with the shadcn `FieldGroup` / `Field` set (run `npx shadcn@latest add field`).

### [Medium] `space-y-*` / `space-x-*` used instead of `flex … gap-*`
- **Where**: `src/web/src/components/seller/listings/new-listing-form.tsx:148,169,278,320,346,376,436`; `src/web/src/components/seller/dashboard/today-panel.tsx:8`; `src/web/src/components/seller/analytics/{top-products.tsx:11, conversion-funnel.tsx:11, sources-donut.tsx:49}`; `src/web/src/components/ui/form.tsx:91`.
- **Issue**: The `shadcn` styling rules explicitly forbid `space-x-*`/`space-y-*` because they break with `gap-*`-based primitives and cause RTL/flex-direction surprises. The fact that `FormItem` itself emits `space-y-2` makes every form propagate the smell.
- **Skill rule**: `shadcn` -> `rules/styling.md` ("No `space-x-*` or `space-y-*`. Use `flex` with `gap-*`.").
- **Fix**: Convert these wrappers to `flex flex-col gap-2`/`gap-3` and update `FormItem` to `flex flex-col gap-2` (after the Form migration above).

### [Medium] `w-N h-N` pairs instead of `size-N`
- **Where**: `src/web/src/app/seller/first-order/page.tsx:138,148`; `src/web/src/app/seller/first-month/page.tsx:223`; `src/web/src/app/seller/listings/page.tsx:119`; `src/web/src/app/seller/listings/[sku]/preview/page.tsx:45,161,165`; `src/web/src/app/seller/listings/[sku]/edit/page.tsx:96`; `src/web/src/app/seller/welcome/page.tsx:97`; `src/web/src/app/seller/states/empty-orders/page.tsx:44,58`; `src/web/src/app/seller/analytics/page.tsx:79,83,87`; `src/web/src/app/seller/orders/[id]/pack/page.tsx:159`; `src/web/src/components/seller/listings/new-listing-form.tsx:362,401-402`; `src/web/src/components/seller/shell/sidebar-nav.tsx:52`; `src/web/src/components/seller/orders/order-detail-customer.tsx:11`.
- **Issue**: Whenever width equals height the `shadcn` styling rules require `size-N`. About a dozen call sites still ship `w-8 h-8`, `w-14 h-14`, `h-2 w-2`. Most of these are icon containers and avatars where the rule was written to catch.
- **Skill rule**: `shadcn` -> `rules/styling.md` ("Use `size-*` when width and height are equal").
- **Fix**: Mechanical search-and-replace of `w-N h-N` / `h-N w-N` -> `size-N`.

### [Medium] `--font-display` / `--font-text` tokens are defined but never used
- **Where**: `src/web/src/app/globals.css:63-68` defines `--font-display: "SF Pro Display" …` and `--font-text: "SF Pro Text" …`. A repo-wide grep for `font-display` / `font-text` returns zero hits in shipped TSX (only the variable definitions). `DESIGN.md:69-93` mandates SF Pro Display for headlines and SF Pro Text for body — the entire typography ladder ("hero-display 56/600/-0.28", "display-lg 40/600", "body 17/400/-0.374") is documented but never assigned to elements.
- **Issue**: The token system exists but headlines fall back to `font-sans` (Geist) and use ad-hoc `text-[15px] / text-[20px] / text-[24px] / text-[32px]` instead of the documented `display-lg` / `display-md` / `body` scale (see `app/seller/listings/[sku]/preview/page.tsx:53,131,182`, `app/seller/welcome/page.tsx:38`). Negative letter-spacing (`tracking-hero`, `tracking-display`) defined in `globals.css:137-138` is also unused.
- **Skill rule**: `building-components` `design-tokens.mdx`; `ui-ux-pro-max` §6 `font-scale` and `text-styles-system` ("Use platform type system").
- **Fix**: Expose typography classes (`text-display-lg`, `text-body`, `text-tagline`) via `@theme inline` `--text-*` tokens or a small CSS layer that pairs `font-display` + `tracking-display` + the right size/leading, then replace the ad-hoc `text-[Npx]` usages with those classes.

### [Medium] Seller shell uses raw hex for foreground & background instead of theme tokens
- **Where**: `src/web/src/app/seller/layout.tsx:10` -- `bg-white text-[#1d1d1f]`.
- **Issue**: The seller layout is the literal shell that wraps every seller page; it pins the entire surface to a light-mode hex literal and `text-white` instead of `bg-background text-foreground` (which `globals.css:199-201` already wires up). This single line is what breaks any future dark mode rollout: even if every leaf component used semantic tokens, the shell would still force white/`#1d1d1f`.
- **Skill rule**: `tailwind-design-system` "Base styles" pattern (`body { @apply bg-background text-foreground }`); `shadcn` -> `rules/styling.md` ("No manual `dark:` color overrides. Use semantic tokens").
- **Fix**: Change to `<div className="grid min-h-screen grid-cols-[240px_1fr] bg-background text-foreground">`.

## Not flagged (intentional)

- **No `tailwind.config.{js,ts}`** in `src/web/`. Correct for Tailwind v4; the CSS-first `@theme inline` block in `globals.css` is the only configuration surface.
- **shadcn components customized in-tree** (e.g., `Card` has a `data-size="sm"` variant, `AlertDialog` exposes `AlertDialogMedia`, `Button` exposes `xs`/`icon-xs`/`icon-sm`/`icon-lg`). Per `shadcn` skill this is the supported workflow.
- **`AlertDialog` overlay uses `bg-black/10 … backdrop-blur-xs`** instead of a 40-60% scrim. The shipped product follows the Apple-style soft scrim documented in `DESIGN.md`; the `ui-ux-pro-max` 40-60% recommendation is for mobile/native and is explicitly waived by the project's design.
- **`Select` aligned with shadcn defaults** (recent fix `c5aaef4f`). `SelectValue` now renders inside the trigger with proper `data-placeholder` styling, and the chevron uses `SelectPrimitive.Icon`.
- **"Mira" string** appears only in `src/web/src/lib/seller/application/data.ts:9` (`shopName: "Mira Studio"` on `/seller/apply`) and in marketing test files asserting its *absence* elsewhere. The brand-copy rule is being enforced by tests; no copy bugs found.
- **shadcn `Form` directive `"use no memo"`** is documented as known debt with a TODO and a MEMORY note — flagged in finding #7 above so it is tracked but not duplicated here.
- **Hi-fi reference JSX** (`design/project/hifi-*.jsx`) was not audited — reference assets, not shipped code.
